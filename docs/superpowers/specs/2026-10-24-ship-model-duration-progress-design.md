# Длительность и прогресс `/4` — короткий дизайн

## Намерение

Новый обычный опыт модели корабля `/4` по умолчанию длится **3600 модельных секунд**. Во время долгого расчёта игрок видит прошедшее модельное время, полный горизонт и процент выполнения; графики продолжают обновляться.

## Текущее нарушение

- Главный Ship Fitting уже использует `3600`, но отдельный экран `/4` и fallback его builder используют `60`.
- Экран `/4` передаёт Worker `maxSteps: 1`, поэтому Worker возвращает результат и UI полностью перерисовывает графики после каждой модельной секунды (для governor — после каждого тика 30 Гц). Это сохраняет данные, но делает длинный прогон неоправданно медленным.

## Выбранный подход

- Один общий default `3600` для fresh ordinary `/4`: workspace, builder и видимый input. Импортированный опыт/result/checkpoint сохраняет собственную длительность без миграции.
- В нижней панели `/4` показывать `<progress>` и текст `t / H с · N%` для ordinary и governor режимов. Значение берётся только из принятого Worker snapshot; графики и прогресс поэтому относятся к одному состоянию.
- Start и checkpoint отправляют существующему Worker пакет до `2000` шагов. Уже существующий wall budget `80 ms` остаётся верхней границей одного вычислительного пакета; после каждого пакета UI принимает snapshot, обновляет графики и подтверждает telemetry. Pause/Cancel проходят между пакетами.

## Не делаем

- Не меняем физику, шаг модели, retention, Worker protocol, результаты импорта или ТТХ.
- Не скрываем графики на время расчёта и не вводим ETA.
- Не меняем основной Ship Fitting, где default уже равен `3600`.

## Приёмка

1. Fresh `/4` input и экспортируемый spec содержат `durationSeconds: 3600`.
2. Импортированная длительность сохраняется буквально.
3. Во время незавершённого расчёта видны elapsed/total/% и доступна Pause.
4. Главный browser gate воспроизводит операторский сценарий: fresh `/4` → preset `sputnik-d` («Северин Спутник · D») → `3600 с`. Прогон завершается без ошибки, с видимыми графиками и финальным `3600 / 3600 с · 100%`; лимит — не более 20 секунд на штатной CI-конфигурации.
5. Ordinary и governor Start/checkpoint используют тот же bounded batching; физические результаты остаются детерминированными.
6. Отдельный длинный browser-сценарий успевает увидеть промежуточный прогресс, доступную Pause и успешный переход в `paused`, не подменяя главный gate укороченным прогоном.
