# Чистка информации о модуле

**Источник WHAT:** прямое поручение оператора 2026-10-07 и приложенный снимок
окна установки. Убрать лишние/неприменимые поля и итоги всей сборки из карточки;
служебную информацию сохранить под маленькой кнопкой. Объём изделия не является
используемой характеристикой. Это уточнение представления UI v4, не новая модель.

**Цель:** выбирать модуль по его характеристикам, без служебной простыни.
**Режим:** PRODUCT, одна небольшая UI-задача ulab-p2w, default budget5:
Plan Review1 → Developer → QA2 → scoped Review3; два вызова резерв.
**База:** ebd481433b0de027625d8970d14a32aa75245970, отдельная ветка
feat/module-card-cleanup в существующем изолированном checkout. Проверенная
thermal версия/Pages/LAN остаются доступны до нового принятого build.

## Представление

- В строке кандидата: название, калибр, профильный номинал/ТТХ и собственная масса.
  Грузовой отсек: тип трюма, собственные SCU и масса. Лазер: мощность и собственный
  номинал добычи по текущему процессу; без суммы лазеров/добычи всей сборки.
  Другие семейства показывают свои ёмкость, тягу, выдачу или параметры охлаждения
  из существующих чисел; не придумывать новые характеристики.
- Не показывать неприменимые/нулевые показатели чужих семейств, «производитель
  не указан», сырой family, неизвестный объём изделия, тепловой material bill,
  SHA/пути источников и служебный текст о колонках по умолчанию.
- Компактная «i» с понятным accessible name раскрывает существующие технические
  подробности/ТТХ/источники. Эти данные не удаляются. Не вкладывать интерактивную
  кнопку/disclosure в кнопку выбора кандидата или карточку слота.
- Предпросмотр всей сборки сохранить в свёрнутом блоке «Изменения сборки»;
  сравнение результатов в основном рабочем пространстве остаётся прежним.
- Сортировку по количеству лазеров убрать. Вместимость сортировать по самому
  модулю, а не всему кораблю; назвать «Вместимость», не «Объём изделия».
  В заголовке не показывать служебный «Источник» и неприменимые метрики; источник
  при необходимости остаётся вариантом существующего раскрываемого select.
- У установленных модулей также убрать отсутствие производителя и неподходящие
  сообщения об отсутствующем канале. Сохранить реальные измерения, устаревший
  результат и предупреждения: скрытие служебного текста не прячет ошибки.
- Footer: версия интерфейса4.1; версия модели/каталога не меняется.

## Scope / владельцы

Основные: `src/app/fitting-ui/swap-dialog.ts`, `ship-view.ts`,
`instance-details.ts`, `presentation.ts`, `src/app/fitting.css`.
`src/app/fitting.ts` — только необходимая привязка disclosure/фокуса и версия.
Существующие сценарные browser tests актуализировать по новому представлению.
Один Developer; PM пишет документы/ведёт Beads/публикует. Не реорганизовывать app.

OUT: расчёт, runner/Worker, TTX/catalog, физика, JSON/CSV schemas, сохранение,
новые библиотеки, новые экраны, GDD U2, H₂ governor, численный износ.

## Verification / Review Contract

| AC | Проверяемое поведение | Метод |
|---|---|---|
| MC01 | Грузовой отсек показывает собственные тип/SCU/массу; нет видимых лазеров, добычи,0потребления, итогового трюма и объёма изделия. Лазер и представители остальных существующих семейств имеют профильные ТТХ | Actual styled DOM/визуальный просмотр desktop и touch390; перебор всех семейств по их данным, не новая матрица симуляции |
| MC02 | Служебные подробности скрыты, доступны через маленькую «i»; сведения читаемы и экранированы, фокус/клавиатура/touch работают; раскрытие не выбирает/не устанавливает изделие | Один настоящий выбор другого кандидата + «i» у соседнего; состояние монтажа до/после; Tab/Enter/Space/Escape по необходимости |
| MC03 | Поиск, семейство/размер, сортировка, выбор, отказ несовместимому, одиночная/batch замена, снятие/закрытие и возврат фокуса сохраняются. Optional предпросмотр доступен | Одна bounded сквозная fitting цепочка; существующая browser regression group |
| MC04 | Та же чистка у установленных/встроенных карточек; сведения и измерения доступны, stale/несовместимость не скрыты; footer4.1 | Установить cargo/laser, посмотреть карточки и встроенное изделие; короткий Start/Pause + сведения/состояние |
| MC05 | Никакой новой численной поверхности: model/runner/fitting/catalog/io/workspace blobs прежние, действия читают/применяют прежние значения | Git blob equality к базе, обычный typecheck/build/test guard; browser ownership regression. Не повторять4physical/81digests/hour/12h кампании |

Review IN: только changed UI/test paths и необходимые callers; риски nested
controls/случайной замены, скрытого предупреждения, неверного профильного числа,
sort normalization, mobile overflow и потери existing actions. BLOCKER только
AC/regression/correctness/build; косметическая форма — ADVISORY, не авторасширение.

## Реализация и доставка

1. Plan Review по MC01–05, затем Draft PR с этим HOW до product-кода.
2. Developer делает одну компактную правку общего представления и действия «i».
   Для reversible текста не писать зеркальные unit tests; смысловая browser
   регрессия обязана ловить случайную установку/выбор и потерю действий. Обычный
   guard перед commit, один immutable build/source binding и краткий отчёт.
3. QA по таблице, один scoped Code Review; только affected fix при named FAIL.
   После3 review/QA+triage итераций короткий аудит PM_ERR/DOC_PR. Показать новый
   LAN build и опубликовать принятую правку на существующую Pages; сохранить
   первую Lab и старые hashed assets. Никаких новых портфелей evidence/guards.

Rollback: прежний immutable a6 build/Pages commit b2842bc; сохранённые результаты
и сборки не мигрируются. Source PR остаётся Draft до внешних base/operator gates.
