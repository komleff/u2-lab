# Цель

После нажатия «Запуск» Лаба либо начинает измеряемый расчёт, либо быстро и явно
сообщает, что расчётный Worker недоступен. Состояние «Выполняется / ожидается
измерение» не может навсегда оставаться на `0 с`.

Наблюдённый дефект: вкладка `127.0.0.1:4197` была восстановлена Chrome из кэша при
остановленном сервере. UI создал active run, но три владельца Worker не обрабатывают
`Worker.onerror`/`messageerror`; поэтому run остался активным без ACK и измерений.
На том же SHA при живом сервере `127.0.0.1:4198` Worker дал `start ACK`, время пошло,
Pause/Cancel остались доступны. Значит, физическое ядро не является источником этого
конкретного зависания.

# Scope

- Обработать транспортный отказ Worker во всех трёх существующих UI-владельцах:
  основной Ship Fitting, экспериментальная модель корабля и Legacy.
- При отказе очистить pending-команды, снять active run через существующий abort/reset
  boundary, показать понятную ошибку и оставить страницу отзывчивой.
- Не менять Worker protocol, физику, численные параметры, глобальные test timeouts,
  модель/схему/каталог и сохранённые документы.
- Обновить видимую версию Лабы `v2.3 → v2.4` при неизменной версии интерфейса
  `UI v4.8`; технический package patch `0.2.0 → 0.2.1`.
- Публикация Pages выполняется только после operator merge и отдельного smoke; этот PR
  не обновляет `gh-pages` сам.

# Реализация и границы

Сначала добавляется минимальный failing browser test на реальный Worker load failure.
Production-код появляется только после подтверждённого RED. Исправление использует
существующие abort/reset методы рабочих пространств и не создаёт новый runtime или
новую подсистему восстановления.

Rollback: revert hotfix PR. Versioned model/state/catalog данные от него не зависят.
