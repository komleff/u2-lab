# Локальный запуск

Рабочая ветка — `feat/claude-design-ui`. Для сборки нужны Node >=22.12 и npm:

```bash
npm ci
npm run build
python3 -m http.server 4183 --bind 0.0.0.0 --directory dist
```

Откройте `http://localhost:4183/` на хосте или `http://<LAN-IP>:4183/` на устройстве
той же сети. Готовый standalone запускается последней командой из папки распакованного
архива. Шрифты и изображения входят в сборку. Для текущего стенда оператора адрес —
`http://192.168.68.65:4183/`; после замены сборки обновите страницу.

Предыдущая версия Ship Fitting оставлена на `http://192.168.68.65:4186/`.
Первый интерфейс Power & Heat с прежними графиками и полями доступен на
`http://192.168.68.65:4186/?mode=legacy`. Это сохранённый интерфейс Legacy;
он работает на существующем численном ядре, а не обещает историческую архивную сборку.

# Работа со сборкой

Оснастка, Power & Heat и сравнение используют общее состояние. Переход между ними
сохраняет тест. Выберите сменный слот, посмотрите совместимость и предпросмотр всей
сборки, затем примените замену. Встроенные изделия отмечены замком; их параметры входят
в сводку и расчёт. Пакетная замена доступна для сменных слотов полезной нагрузки.

Варианты A/B/C и добавленные варианты хранят отдельные сборки и результаты в памяти
страницы. JSON сохраняет выбранную сборку; весь набор вариантов автоматически не
сохраняется. При правке сборки прежнее измерение получает пометку устаревшего результата.

Один тест выполняется для своего варианта и ревизии. Его условия заблокированы во время
работы и паузы; правки оснастки готовят следующую ревизию. Переключение варианта не
переносит на него чужой результат. Снимок теста A в лаборатории — отдельный неизменяемый
результат для сравнения, его имя не означает вариант сборки A.

Каналы и журнал показывают доступную выборку истории с подписью её границ и количества.
Номинальные значения отделены от измерений; отсутствующие показатели явно обозначены.
Экспорт JSON/CSV использует прежние форматы. Маршрут `?mode=legacy` открывает прежний
Power & Heat для поддерживаемых данных Legacy.

Текущий лабораторный сценарий сохранён. Реальный шахтёрский рейс, добыча до полного
трюма и заправка на станции отложены оператором в отдельную задачу.

## Повторный запуск и сохранённый результат

После нового «Запуск» Лаба ожидает первое измерение нового runId. Прежний результат
сохраняется в варианте и обозначается как предыдущий; его экспорт сохраняет прежний
RunSpec. Снимок A не меняется автоматически. При выборе другого варианта во время
активного теста заблокированные условия и детали Лабы показывают active RunSpec;
подготовленные условия следующего варианта сохраняются до его собственного запуска.
