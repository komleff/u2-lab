# Обновления ГДД и спецификаций кораблей U2

U2 требуется синхронизация правил энергетики, тепла, маскировки и корабельных паспортов с принятыми решениями U2 Lab. Главная работа — уточнить действующих владельцев и заполнить недостающие ТТХ, сохранив происхождение каждого значения.

Список основан на принятом PR #19, плане обновления Лабы в PR #20, открытом корректирующем PR #21, документальных PR U2 #842/#843/#848 и профильных источниках U2. PR #20 изучен вместе с полным планом и двумя раундами независимого ревью; из #848 учтены принятые классовые различия оснащения и явная сверка Quiet. PO подтвердил сохранение границы прочности по действующему ADR-0066. **Северин Караван** следует действующему каталогу U2, а не отдельному новому решению PO в этой сессии. Противоречащие этим источникам места в документах Лабы требуют исправления.

## Что PR #20 добавляет к пакету обновлений U2

PR #20 организует реализацию уже выбранной модели: D0 — синхронизация источников; T1 — данные и состояние; T2 — автоматика и баланс; T3 — буфер и тепловые поверхности; T4 — прочность и сохранение; T5 — маскировка, сигнатуры и объяснение результата; T6 — опыты и приёмка. Для ГД U2 из этого следуют следующие дополнения к списку.

| Требование плана | Что закрепить в документах U2 |
|---|---|
| Синхронизация до серверной реализации | Принять согласованный пакет ГДД/спецификаций и адресных ADR-изменений до начала отдельного серверного переноса и до заявления SM-14 о совпадении расчётов. Документы U2 могут готовиться параллельно с реализацией Лабы. Изменение границы прочности из базового §1 PR #20 исключить: действует ADR-0066; исправление уже подготовлено в PR #21 |
| Явные версии и происхождение чисел | В паспортах, компактных данных и контракте передачи различать версию каталога, модели и состояния, принятую норму и кандидат. План Лабы назначает u2-lab/4, ship-fitting-ship-model-0.1 и ship-fitting-0.3.0; это версии Лабы, а не автоматически новые номера формата U2. Старые опыты сохраняют исходные числа и результат; новый расчёт из старой сборки требует явного преобразования с показом изменений |
| Полное состояние продолжения | Дополнить контракты экземпляра и сохранения: температурная метка оставшегося запаса буфера, температура входа в маскировку, состояния автоматики/генератора/защит, факт первого ухода прочности ниже нуля, накопленная аварийная работа, кулдаун и состояние случайных отказов. Пауза, повторное открытие и смена режима не обнуляют долг или риск |
| Общий профиль сравнения с шагом 1 с | Зафиксировать входы, моменты выбора ступеней, запросы и конечные состояния в CP-01–05. Внутри интервала исчерпание запаса или критическая граница прекращают недопустимую работу, но не дают резервной ступени включиться раньше следующей границы управления. PL определяет интеграцию с быстрым циклом полёта U2 |
| Экранирование связано с тепловой автоматикой | Дополнить Signal/Power/Thermal owners единым учётом: фактические электрические ступени → ушедший наружу и задержанный EM → тепло корабля. Проверка «экран выключен/включён» должна одновременно подтверждать сохранение энергии, рост тепла, влияние на автоматику и ухудшение собственных антенн |
| Ограниченный первый набор кораблей и опытов | Первый набор плана — Спутник S, Мир M и отдельная стелс-сборка; полный каталог и экономика вне этой поставки. Для каждого кандидата хранить исходные данные, условия, версии и полный цикл работа → восстановление → повтор. Проверки G1/G10/G20 не утверждают неизвестную кривую автоматически |

**Прочность: исправление подготовлено в PR #21.** В базовом PR #20 §1 ещё предлагает изменить ADR-0066 на остановку при нуле. PR #21 исправляет план (§1, §3, T1, T4, SM-08, §8), модель, ТЗ и зависимые формулировки: первый обязательный отказ происходит при переходе R≥0 → R<0. При R=0 прочность не останавливает модуль. После первого ухода ниже нуля действуют шанс запуска, риск последующих отказов и кулдаун действующего U2 ADR; новый ADR для этой границы не нужен. До объединения PR #21 с базой различать эти версии текста.

**Обновление после независимого ревью PR #20.** Первый раунд на HEAD 6caf476 потребовал: (1) провести новые версии через создание сборки, проверку, импорт, запуск в Worker и продолжение сохранения; (2) связать задержанный экраном EM с тепловым балансом до фиксации теплового ядра. В HEAD bad4ad5 оба адресных исправления включены в план: добавлены владельцы всего пути версии/сохранения, явное преобразование старой сборки и единый EM/тепловой учёт в T2; T5 только читает его выходы. Повторное affected re-review на bad4ad5 дало PLAN_READY без блокеров. Это заключение относится к проверенному HEAD PR #20, а документальные изменения PR #21 требуют отдельной оценки после включения в базу. Требования к совместимости и энергетическому учёту уже отражены в списке U2.

Приведённые в описании PR #20 успешные проверки существующего проекта подтверждают документальную поставку на прежнем runtime. Они не доказывают работу будущей модели v3, серверное совпадение, полноту сохранения или игровой баланс.

### Аварийный генератор в Quiet: принятое разрешение и текущая выработка

PO принял в этой сессии различие между разрешением аварийного запуска и фактической выработкой. При входе в новый эпизод Quiet разрешение выключено. Оно включается при заряде строго ниже 1% и нехватке солнечной генерации/внешнего ввода для текущей разрешённой нагрузки. Уже включённое разрешение сохраняется, даже если нагрузка уменьшилась, другой источник её полностью покрыл или заряд вернулся к 1%. Снимается оно при достижении верхнего порога либо выходе из Quiet. **Механика принята; верхний порог 2% остаётся балансным кандидатом**, а не окончательным ТТХ U2.

Обозначения: s — доля заряда; a — сохранённое разрешение аварийного запуска (0 или 1); s_off — верхний порог выключения, который должен быть строго выше порога включения 1%; для опыта предлагается 2%. P_load — текущая разрешённая электрическая нагрузка; P_solar и P_external — фактическое доступное питание от солнечной генерации и внешнего ввода на общей шине. **Аккумулятор исключён из P_other**, независимо от оставшегося заряда. P_gen,available — доступная мощность генератора с учётом его фактической работоспособности и ресурсов. Все мощности указаны на одной электрической границе, в ваттах.

\[
P_{other}=P_{solar}+P_{external},\qquad
P_{deficit}=\max(P_{load}-P_{other},0).
\]

В Quiet разрешение меняется по условиям:

\[
a_{new}=\begin{cases}
0,&s\ge s_{off},\\
1,&s<1\%\ \text{и}\ P_{deficit}>0,\\
a_{old},&\text{иначе}.
\end{cases}
\]

При выходе из Quiet разрешение снимается; дальнейшую выработку определяет обычная автоматика. Это не приказ обязательно остановить генератор после выхода.

Допустимый запрос генератора в Quiet:

\[
P_{gen,request}=a_{new}\,\min(P_{gen,available},P_{deficit}).
\]

Разрешение не гарантирует успешного запуска и не обходит прочность, температурную защиту, кулдаун, топливо или вспомогательное питание. Фактическая выработка не превышает запрос. Она может падать до нуля без снятия разрешения; при новом дефиците запрос восстанавливается по тому же разрешению. В первом стенде нулевая выработка означает остановку без холостого расхода топлива и собственного IR/EM генератора. Генератор не создаёт зарядный избыток и не восстанавливает аккумулятор. Независимые солнечная генерация и внешний ввод могут восстановить заряд. Если их и генератора недостаточно, оставшийся аккумулятор может участвовать в общем балансе, но его наличие не запрещает разрешённый аварийный запуск и не создаёт бесплатную энергию после исчерпания.

Сохранять a вместе с режимом и состояниями генератора. Пауза, экспорт/импорт и продолжение того же эпизода Quiet не сбрасывают разрешение. Реальные IR/EM и нагрев считаются по фактической работе; ранее накопленное тепло остаётся частью состояния корабля.

| Проверочный случай | Разрешение и запрос |
|---|---|
| s=1%, разрешение ранее выключено, есть дефицит | Не включается; порог входа строго ниже 1% |
| s<1%, солнце/внешний ввод полностью покрывают нагрузку | Новое разрешение не требуется, запрос генератора равен нулю |
| s<1%, есть дефицит и аккумулятор ещё способен отдавать мощность | Разрешение включается: аккумулятор не считается другим источником для условия входа |
| Разрешение уже включено, другое питание покрыло нагрузку | Разрешение сохраняется, запрос равен нулю |
| При сохранённом разрешении дефицит появился вновь | Запрос появляется без нового пересечения 1% |
| Заряд между 1% и верхним порогом | Сохраняется предыдущее разрешение |
| Заряд точно достиг s_off | Разрешение снимается; для опыта s_off=2% как кандидат |
| Генератор неисправен/нет топлива/запуск ещё не разрешён защитой | Разрешение не отменяет физическую недоступность; фактическая выработка равна нулю |
| Выход из Quiet | Аварийное разрешение снимается, действует обычная автоматика |

| Управление | Обычная тяга и момент, фактически доступная доля при ограничениях, профиль автоматики, разрешённые режимы |
| Обзор и заметность | Собственные сенсоры и цена покрытий; IR/EM/CS раздельно; оценка дальности с явно указанными наблюдателем, средой, ракурсом и состоянием |
| Рабочий цикл | Полезная производительность, время заполнения трюма, возврат, разгрузка, восстановление заряда/буфера, ресурс на полезную работу |
| Готовность | Принятое значение / кандидат / расчётное производное; воспроизводимый опыт; готовность игрового и производственного состава по Master |

Каталоговые эффективные площади, независимые от 3D-модели, **предложены**, но ещё не оформлены как новый нормативный владелец U2. До закрытия этого решения паспорт может хранить кандидаты площадей с происхождением. Уже замкнутая конструкция пассивного радиатора S/Civilian/G0 в Master TTX (490 м² поверхности × ε 0,90 = K_rad 441 м²) сохраняет своё обоснование; новые балансные площади требуют явной сверки с этим владельцем и будущими семействами.

Температура после стоянки в ангаре, длительность маскировки и дальность обнаружения — результаты состояния и условий. Они не становятся постоянными ТТХ корпуса. Принятый ангарный обмен относится к будущему серверу и не добавляет фиктивную площадь радиатора в паспорт корабля.

## Открытые решения и уточнения

1. **Эффективная площадь и конструкция радиатора.** Модель Лабы предлагает балансные площади без зависимости от готовой 3D-модели. Master TTX уже обосновывает конкретный пассивный радиатор S/Civilian/G0 через материал, покрытие, геометрию и развёртывание; для будущих классов/поколений конструкция ещё открыта. PO должен определить область применения новых эффективных площадей и способ сверки с существующим изделием; затем обновляются соответствующие владельцы, а не только цифры. Не приписывать ADR-0043 универсальное требование готовой 3D-модели для каждой балансной площади.

2. **Критическая защита особых режимов.** Принятое направление — особый режим задаётся корпусом и отключает обычное снижение мощности; старый U2 ограничивает военный override сочетанием класса корпуса/модуля. В итоговом правиле требуется однозначно указать допустимость работы за верхней/нижней критической границей и условия повторного запуска. Короткая фраза «особые режимы следуют исключениям» не заменяет эту таблицу.

3. **Класс и поколение температурных пределов.** Проверка G10/G20 и дальнейшего предела поручена, но окончательная матрица и кривые ещё не определены. Конкретные 500→490 K, 540→530 K и предлагаемые сдвиги не становятся универсальными ТТХ. Сжатие ступеней для узкого рабочего коридора также остаётся кандидатом.

4. **Несколько теплообменных полей.** Наличие отдельного h принято; Лаба рассматривает не больше одного поля на фазу. Нужен владелец наложения полей U2: фон, знаковый обмен, площади горячих контуров и отсутствие двойного учёта одного источника.

5. **Численный перенос.** PR #20 конкретизирует общий дискретный профиль 1 с, CP-01–05 и отдельный слой теплового управления, сохраняя быстрый полёт. Это целевой контракт сравнения; архитектура его реализации в U2 остаётся у PL, включая совместимость с текущей физикой/сетью 30 Гц, окончательные допуски и вычислительную стоимость. Состав сохраняемого состояния уже перечислен в плане и должен быть полным. Допуск для энергии и температуры нельзя заменять обещанием одинакового мгновенного EM-пика при разных шагах.

6. **ТТХ кандидатов.** ИИ готовит недостающие параметры Спутника, Мира и стелс-репера; PO оценивает результаты опытов. Полный ручной ввод каталога или новый редактор физических законов не требуется. Конкретную кривую роста полезной мощности лазера ещё нужно предложить и проверить.

7. **Численная цена холодного Stealth и сенсорные исследования.** Закон холодного H₂-сброса выбран для следующего этапа; остаются ΔT_stealth, упреждение и гистерезис. Проверить полный IR относительно спокойного обычного корабля того же размера/поколения при одинаковых фоне, ракурсе и наблюдателе; одно совпадение температуры газа с фоном не гарантирует незаметность всего корабля. Пассивный radar ping и движущиеся пары — отдельная программа. Временные IR-коэффициенты приняты для Лабы и имеют иной статус, чем ещё не выбранный ΔT.

Принятые решения об имени категории, печах, отсутствии потолка тяги, холодном IR-контрасте и областях двух насосных изделий повторного выбора не требуют. Нужны их корректная фиксация и проверка.

## Проверка перед передачей реализации

Это условия будущего принятия параметров и реализации, а не заявление о прошедших runtime-тестах.

- Электричество: полный и пустой аккумулятор, ограничение источника, температурная остановка и прямое питание; потери учтены один раз.
- Тепло: горячий/холодный фон, поле, обычная обшивка и горячие контуры; поверхность не попадает в два контура.
- Классы радиаторов: равные полные тепловые ватты при разных профилях с носа/кормы; обычный радиатор на Military не меняет версию; горячая сторона TI наследует профиль своих поверхностей; смесь версий не теряет площадь и не считает её дважды.
- Оснащение классов: RAM, буфер и оболочка имеют разные состав/массу/цену; изменение оболочки проверяется на холодном и горячем фоне; Military не получает Маскировку от одного буфера/радиатора.
- Буфер: мощный короткий пик, длительная нагрузка, работа → восстановление → повтор; сохранение долга; недостижимая разгрузка.
- Автоматика: чувствительный выключенный модуль, отсутствующая ступень, равные пороги, холодный старт без доступного питания.
- Маскировка: манёвр на полном запросе, запреты демаскирующих средств, одинаковый наблюдатель, цена экрана для собственных сенсоров.
- Quiet: проверить вход ниже 1% при дефиците без включения аккумулятора в другое питание; сохранённое разрешение при нулевой выработке; повторный запрос при новом дефиците; равенство верхнему порогу и выход из режима; продолжение сохранения без сброса разрешения. Генератор не заряжает аккумулятор. 2% — кандидат. Выстрел/radar ping/наружная передача не создают выброс и не выключают режим; фоновые задачи и необязательная зарядка стоят; пассивные приборы и реальные важные нагрузки учитываются.
- Экранирование: сравнение включённого/выключенного экрана одновременно замыкает электричество/EM/тепло; задержанная энергия меняет температуру и автоматику, собственная антенна теряет чувствительность.
- Прочность: R=0 не вызывает отказа; первый переход R≥0 → R<0 обязательно останавливает модуль; далее шанс запуска, риск за время работы, кулдаун, аварийный предел и температурные запреты по ADR-0066. Ремонт обратно в R≥0 восстанавливает правило следующего первого отрицательного перехода.
- Прогрессия: G1/G10/G20 и дальнейший предел на одинаковой задаче и на усложняющейся задаче; отсутствие универсальной сборки для всех экстремальных сред.
- Перенос: одинаковые полные входы общего профиля дают одинаковые ступени/разрешения/запросы; конечные состояния соответствуют согласованным допускам; игровой клиент получает только разрешённое знание.
- Продолжение: CP-05 сравнивает 59 с → сохранение → ещё 1 с с непрерывными 60 с; совпадают запасы, запросы, отказы, случайное состояние и кулдаун. Повторный импорт не даёт новой попытки удачи. Повреждённое/неподдерживаемое состояние отклоняется целиком; старый результат открывается без пересчёта.
- Источники IR/H₂: фактические моторные потери отделены от потерь тракта; нулевой запрос/пустой бак прекращают унос; фон вычитается один раз; холодный базовый газ не вычитает горячий корпус. Стандартный/продвинутый старые приёмники и новая целевая норма имеют явные версии.
- Ангар: при 500/400/300 K отдельный поток равен 2/1/0 МВт; обслуживание и офлайн используют реальное время; переустановка модуля не сбрасывает T_ship, а меняет только дальнейший интервал. Это будущая серверная проверка, не заявление о готовности Лабы.

Существующие правила общей температуры, единого аккумулятора, конечного буфера и физической массы сами по себе не новые. Новое — перечисленные уточнения поведения, владельцев, данных и проверяемых границ.

## Глоссарий

| Термин | Значение |
|---|---|
| ТТХ | Характеристики корпуса, модуля или готовой сборки |
| Владелец нормы | Документ или набор данных, который определяет действующее правило |
| TI | Термоинвертор, тепловой насос |
| IR / EM / CS | Инфракрасная заметность / электромагнитное излучение / радарное отражение |
| Уставка | Температура, которую удерживает автоматика |
| Тепловой долг | Тепло конструкции и буфера, которое нужно вывести перед повторением полного цикла |
| Кандидат | Предложенное значение для опыта, не утверждённый параметр U2 |
| CP-01–05 | Общие контрольные опыты для дискретного расчёта и продолжения сохранения |
| SM-01–14 | Критерии приёмки модели корабля и её переноса из ТЗ Лабы |
| Кулдаун | Пауза перед следующей попыткой запуска |
| Случайное состояние | Сохранённая последовательность случайных отказов; повторное открытие не меняет уже определённый ход опыта |
| PLAN_READY | Независимое ревью признало план готовым к исполнению |
| Quiet / Маскировка | Соответствующее особое состояние Stealth; конкретные разрешения заданы итоговой таблицей, а не старым потолком тяги |
| Направленный радиатор | При том же полном тепловом выбросе по-разному виден с разных ракурсов |
| Управляемая оболочка | Реальное оснащение корпуса, изменяющее эффективную площадь теплообмена в заданном диапазоне |
| Газовый IR-контраст | Добавочный сигнал выброса H₂ относительно фона; отличается от вывезенной тепловой энергии |
| Неразрешённый контакт | Несколько источников, которые прибор пока видит как одно пятно |
| G_hangar | Тепловой контакт ангара с кораблём, в кВт/К |
| ΔT_stealth | Допустимое превышение температуры холодного H₂-сброса над фоном; численное значение ещё выбирается |
| Разрешение аварийного генератора | Сохранённое право запрашивать запуск в Quiet; отличается от успешного запуска и текущей мощности |
| Верхний порог выключения | Заряд, снимающий аварийное разрешение; 2% предложено для баланса, но не утверждено как окончательное ТТХ |
| PO / PM / PL | Владелец продукта / ведущий поставки / технический планировщик |
