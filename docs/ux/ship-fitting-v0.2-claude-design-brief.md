# Задание для Claude Design

Собрать HTML или SVG макет главного экрана **U2 Ship Fitting**. Это браузерный инструмент
для подбора корабельной оснастки и проверки её добывающей работы. Пользователь выбирает
корпус, устанавливает модули в слоты, запускает Power & Heat и сравнивает результат.
Цель экрана: за несколько секунд понять «что установлено», «что мешает работе» и
«какую замену стоит проверить». Всё необходимое для макета приведено в этом файле.

Принятое продуктовое поведение задано GDD и SF01–20. Здесь геометрия и визуальная
подача — предложения для макета; дизайнер может улучшить их, сохраняя содержимое,
информационную иерархию и взаимодействия. Не создавать новые игровые правила.

## 1. Результат работы

1. Главный desktop экран1440×1100px: fitting, выбранный слот, каталог и результат опыта.
2. Мобильный390px вариант того же экрана, допускающий вертикальную прокрутку.
3. Состояние preview замены модуля с дельтами до применения.
4. Состояния «неполная сборка», «опыт выполняется» и «задача не завершена» — отдельные
   экраны/артборды либо переключаемые состояния в HTML.
5. Вид сравнения1/2/3лазеров. Можно как секцию ниже основного экрана.

HTML предпочтителен для проверки поведения и адаптивности: автономный файл с CSS,
без сборщика, внешних библиотек, сетевых запросов и реальной физической симуляции.
SVG допустим как набор именованных артбордов. Тексты и цифры должны оставаться читаемыми.
Иллюстрация корабля необязательна; SVG-силуэт — спокойная второстепенная деталь.

## 2. Пользователь и основные действия

Пользователь понимает смысл генератора, аккумулятора и лазера, но не обязан знать формулы.
В начале он берёт готовый пресет, меняет один модуль и запускает опыт. Позже сравнивает
две–три сборки. Для обычного монтажа не нужен JSON и ручной расчёт баланса.

Главные действия: выбрать корпус/пресет → выбрать слот → посмотреть подходящие модули
→ сравнить замену → применить → запустить опыт → сравнить результат.
Сохранение неполной сборки разрешено. Run запрещён при отсутствии обязательного оборудования
или структурной ошибке сценария. Нулевые запасы — предупреждение; комплектный корабль
может получить честный неудачный опыт. Нехватка мощности/охлаждения не запрещает монтаж.

## 3. Иерархия и desktop размещение

Внешние поля24px, интервалы16px. Рабочая ширина1392px. Верхняя панель64px.
Затем краткая полоса статуса/результата, после неё три колонки280/720/360px.
Ниже — результаты Power & Heat и сравнение. Страница прокручивается, важные действия видны
без поиска в нижней части. Избегать нескольких больших вложенных областей прокрутки.

| Область | Содержимое | Приоритет |
|---|---|---|
| Верхняя панель | U2 Ship Fitting; разделы «Оснастка», «Power & Heat», «Сравнение»; Сохранить/Импорт | Постоянная навигация |
| Полоса результата | Выбранная задача; комплектность; текущий статус опыта; первая причина ограничения; SCU/час | F1, читается первой |
| Левая колонка280 | Корпус/пресет; size/class/тип движителя; сухая/текущая масса; совместимый груз; запасы | Контекст корабля |
| Центральная720 | Встроенные системы; четыре группы сменных слотов; выбранный слот; предпросмотр замены | F2, основная работа |
| Правая360 | Совместимый каталог для выбранного слота; поиск/семейство/калибр; карточки изделий | F2, выбор |
| Нижняя секция | Условия/сценарий, Start/Pause/Step/Reset, графики, события, measured summary | Power & Heat |
| Сравнение | A/B и явная серия1/2/3, таблица метрик и условия сопоставимости | Решение по опыту |
| «Подробнее» | SI поля, источники, экспериментальные варианты, ledger, JSON/CSV экспорт | F3, по запросу |

Объём каталога не должен отодвигать результат и слоты за первый экран. В desktop выбранный
слот и его preview удобно держать вместе; каталог подсвечивает текущий установленный SKU.
Рабочие показатели группируются по смыслу, а не размещаются десятками одинаковых карточек.

## 4. Слоты и карточка изделия

Четыре группы: «Двигатели», «Питание», «Полезная нагрузка», «Контроль сигнатур».
Для последней подпись: «Тепловое оборудование; обнаружение пока не рассчитывается».
Счётчик заполнения — например «Полезная нагрузка3/3». Пустой обязательный слот виден явно.
March/Retro — одиночные изделия; Strafe/Turn — парные. Русские роли: «Марш»,
«Торможение», «Стрейф — пара», «Поворот — пара».

Карточка слота: название роли/категории, допустимый калибр, установленное изделие,
небольшой набор важных параметров, кнопка выбора/замены. Дубли лазеров подписаны
«Лазер1», «Лазер2», «Лазер3» и управляются независимо. Не объединять их в один модуль×3.
Меньший модуль подходит в больший слот. Несколько маленьких изделий в один слот не помещаются.

Встроенные системы — отдельный видимый блок над сменными слотами. Значок замка означает
«Встроено: заменить нельзя». Их режимы, когда применимы, доступны; масса и потребление
учтены в сводке. Не смешивать замок встроенного модуля и ошибку несовместимости.

Карточка каталога: название, family/калибр, происхождение параметров, масса,
номинальное потребление/выработка или cargo volume, кнопка «Сравнить замену».
Несовместимый вариант можно показать выключенным с конкретной причиной:
«Нужен парный движитель», «Калибр больше слота», «Корпус E не принимает топливный бак».
Preview: «Сейчас / После замены», дельта массы, генерации/потребления, C или cargo/area
по смыслу изделия. Кнопки «Применить замену» и «Отмена». Статические оценки подписаны
«Номинальные параметры», не «Результат работы».

## 5. Полоса F1 и показ результата

Три независимых состояния:
- «Монтаж совместим» либо конкретная structural error.
- «Комплектность: готова / не хватает…»; запасы отдельно.
- «Опыт: ещё не запускался / выполняется / завершён / не завершён в горизонте».

Основная карточка после опыта: добычаSCU и SCU/час; рядом fuelkg/SCU по типам,
H₂kg/SCU, вынужденный простой, восстановление, K_use и первое измеренное ограничение.
K_use показывается процентом и подписывается «Использование добывающей оснастки».
Объяснение по нажатию: «Доля потенциальной добычи выбранных лазеров за полный цикл,
включая перелёт, простой и обслуживание». Рядом всегда абсолютная добыча/час.

Первое ограничение: причина + время, например «Питание ·18,2с». Совпавшие причины
показываются вместе. «Не выявлено за этот опыт» допускается; не обещать бесконечную
устойчивость. Цель достигнута — успех, а не ошибка. Нулевой выход: удельный расход и K
при неопределённом знаменателе — «не определено» с объяснением, без0/Infinity.
Невосстановившаяся сборка: «Не восстановилась за время опыта».

Редактирование во время опыта: спокойная строка «Опыт использует сборку12. Изменения
сохранены в сборке13 и применятся в следующем запуске». Результат A не переписывается.
Ручные приоритеты генераторов/топлива, Kelvin/COP и H₂ exhaust переключатели не добавлять.
Условия среды/сценария доступны; исходные физические параметры — вF3.

## 6. Пример наполнения для макета

**Все результаты ниже иллюстративные**, не результаты физического теста и не новые ТТХ.
Известные nominal anchors допустимы как подписи изделий. Для основной композиции:
IndustrialM, Payload3×M, builtin universal48SCU; три CivilS/G1 laser по3MW.
Power5×M/Signature4×M — принятый лабораторный profile, overall «Экспериментальный».
ГенераторM8MW, аккумуляторS, operating tank, радиатор и utilityH₂ tank/cooler.
Калибр установленного S изделия и максимальный M слота должны визуально различаться.

Выбранный слот: «Лазер3 — PayloadM». Каталог показывает текущий CivilS3MW,
IndustrialS3.4MW и BulkHoldS24SCU/1.8t как альтернативу рабочему лазеру.
На макете важно показать выбор «ещё добывающая мощность или больше грузового объёма».

Демо таблица с одинаковым cycle300s и различающимися fits:

| Сборка | Добыча/цикл | SCU/час | Dieselkg/SCU | H₂kg/SCU | K_use | Первый ограничитель |
|---|---:|---:|---:|---:|---:|---|
|1лазер|9|108|3.0|0.20|48.0%|Тепло|
|2лазера|11.5|138|3.0|0.30|30.7%|Тепло|
|3лазера|12|144|4.0|0.50|21.3%|Питание|

Это визуальный пример небольшого выигрыша третьего лазера при худшем использовании
оснастки/расходе. Не делать badge «лучший корабль» по одному K. Под таблицей — строка
«Одинаковые сырьё, среда, фазы и начальные запасы»; altered conditions меняют её на
«Условия отличаются» с доступным перечнем отличий.

Честные cargo anchors для других карточек: СпутникS builtin6SCU/Payload2×S;
PonyS builtin12SCU+лазер/Payload2×S, поэтому3лазера total допустимы.
SCU — м³ полезного объёма; массовые значения товара зависят от его плотности.

## 7. Mobile390px

Поля16px; одна колонка; удобные touch targets≥44px. Основное действие «Запустить»
доступно в закреплённой нижней полосе с учётом safe area. Краткие статус и результат
остаются перед рабочими панелями. Вместо трёх колонок — разделы «Корпус», «Оснастка»,
«Каталог», «Итог» либо доступный step flow. Изменение выбранного слота открывает каталог
в следующей панели или bottom sheet, с явными «назад/закрыть».

Группы слотов сворачиваются; выбранный слот и причина ошибки остаются видны.
Таблица сравнения превращается в строки/карточки с одинаковым порядком показателей,
а подробная таблица может иметь обозначенную горизонтальную прокрутку. Весь экран
не должен горизонтально прокручиваться. Никаких hover-only подсказок и drag-only монтажа.

## 8. Состояния, визуальный язык и доступность

Сделать инженерный, спокойный интерфейс: тёмная или светлая тема на выбор, высокий
контраст, читаемые цифры, минимум декора. Акцент на основное действие, amber — измеренное
ограничение/предупреждение, красный — structural error, спокойный зелёный — успех задачи.
Цвет дублируется текстом/иконкой. Tabular numerals и единицы рядом с числом.
Body text≈14–16px, metric≈24–32px; избегать плотного мелкого текста.

Происхождение полей: «Из U2», «Расчёт», «Гипотеза». Overall experimental не означает
ошибку fitting. Подробный source/формула/range доступен вF3; SHA/schema strings не
заполняют основной пользовательский экран. Не использовать национальные флаги как readiness.

Показать: пустой обязательный слот, нет выбранного слота, каталог без результатов,
несовместимый preview, zero-stock warning, running/paused/completed, failed import,
график до первого запуска. Ошибка импорта оставляет прошлую сборку и результат на экране.
Клавиатурный фокус виден, кнопки имеют доступные подписи, графики имеют текстовую сводку.

## 9. Чего в макете нет

Покупки/цены/ROI/станционный склад, оружие/бой/обнаружение, игровой3D полёт,
создание аккаунта, физическая проводка, manufacture proof и редактор Kelvin/COP.
Источник питания не является видом движителя; nuclear reactor не помещается вS–L.
Визуальная схема корабля не задаёт пространственные посадочные места вместо слотов.

## 10. Короткий prompt для запуска

«Создай автономный HTML или SVG макет U2 Ship Fitting по приложенному ТЗ. Сначала главный
desktop экран1440px со слотами/каталогом/результатом, затем mobile390px. Покажи preview
замены, running и incomplete состояния, и сравнительную таблицу1/2/3лазеров. Соблюдай
иерархиюF1/F2/F3, различай встроенное/сменное и nominal/measured данные. Демо результаты
пометь иллюстративными. Не реализуй физику и не добавляй новые игровые механики».
